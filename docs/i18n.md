# Internationalization

[中文](i18n.zh-CN.md)

Non-test Go code in this module carries no natural-language strings. Every
prompt, repair instruction, context label, tool and event description and
user-visible line comes from message packs resolved by the `i18n` package.
Machine codes (refusal codes, error codes, JSON field names) stay in code.
Recognition data that is not output, such as the DingTalk gateway's list
of negative reaction names, is configuration of the package that uses it
(`gateway/dws/reactions/`: `default.json` for locale-neutral identifiers, one `<locale>.json` per locale), not a pack.

## Packs

Packs are flat JSON objects stored as `<dir>/locales/<locale>/<domain>.json`
and embedded in the binary of the package that owns them. Values are
strings or lists of strings. All domains of a locale merge into one key
space, so keys are prefixed by their domain.

`i18n.Default()` holds only the loop's packs, embedded by the `i18n`
package. Every other package that speaks embeds its own pack and exposes
`LoadMessages(b)` (merge into a bundle) and `Messages()` (a clone of
`i18n.Default()` with the pack merged, built with `i18n.Extend`). A service
binary therefore ships only the text of the packages it links.

| Pack | Location | Holds |
| --- | --- | --- |
| `contract` | `i18n/locales` (default bundle) | class, mode, lane, session and evidence labels; event summaries of the standard catalog (`event.*`); tool descriptions (`tool.*`) |
| `kernel` | `i18n/locales` (default bundle) | repair and terminal instructions, block labels, event line format |
| `scene` | `i18n/locales` (default bundle) | session roles (`scene.session.<kind>`) |
| `toolhost` | `i18n/locales` (default bundle) | stored text of standard tools (memory records, question options) |
| `employeeloop` | `i18n/locales` (default bundle) | default persona, history line format |
| `memstore` | `store/memstore/locales` | memory digest text |
| `executors` | `taskmgr/executors/locales` | echo executor output (`taskmgr.echo.*`) |
| `stdin` | `gateway/stdin/locales` | stdin gateway lines (`gateway.stdin.*`) |
| `cmd` | `internal/cli/locales` | command flag help and console lines |
| `catalogdoc` | `internal/catalogdoc/locales` | headings and labels of the generated [catalog.md](catalog.md) |
| `runtime` | `prototype/core/locales` | the prototype runtime (`core.Messages()`) |

Shipped locales are `en` and `zh-CN`. Tests require that each package's
locales define **identical key sets** (`Bundle.Parity`), that the default
bundle defines every key the contract catalogs need (`i18n.ContractKeys`)
without relying on fallback, and that it embeds no pack outside the loop
domains.

## Resolution

`Bundle.Resolve(tag)` picks the best loaded locale:

1. canonical form of the tag (`zh_hans` -> `zh-Hans`, `EN-us` -> `en-US`);
2. an exact pack;
3. a script alias: `zh-Hans` -> `zh-CN`, `zh-Hant` -> `zh-TW`;
4. the base language (`en-US` -> `en`);
5. another region of the same language, first in sort order;
6. the fallback, `en`.

`Bundle.Text(locale, key)` looks the key up in the resolved locale, then in
the fallback, and otherwise returns the key itself so the gap is visible.

## Placeholders and lists

- Text placeholders use `{name}`:
  `b.Text("en", "cmd.stopped", "service", "task-manager")`.
- `Bundle.List` returns string lists (for example the prototype's
  example scripts).

## Overrides

`i18n.Default()` is a shared, read-only bundle of the loop's packs (and
each package's `Messages()` a shared bundle with its own pack added). To
change wording without touching code:

```go
b := i18n.Default().Clone()
_ = b.Merge("en", map[string]any{"employeeloop.persona.default": "You are the front desk."})
raw, _ := os.ReadFile("packs/fr/contract.json")
_ = b.Load("fr", raw) // a new locale
```

Pass the bundle to `employeeloop.Config.Messages`,
`scene.KernelRunner.Messages`, `kernel.Options.Messages`,
`toolhost.WithMessages`, `memstore.WithMessages`, `stdin.Config.Messages`
or `executors.EchoExecutor.Bundle`. A `ToolSpec` that
already carries a `Description` keeps it: Host-authored text wins over
`description_key`.

## Choosing the locale of a wake

- Commands: `-locale`, else `EMPLOYEE_LOCALE`, else `en`.
- `KernelRunner.Locale` / `employeeloop.Config.Locale` is the default; the
  locale of the window's last event wins when set.
- Deliveries carry the locale of the window's last event.

## Adding a locale

1. For each pack location in the table, copy `locales/en/` to
   `locales/<locale>/` and translate every value; keep keys and
   placeholders unchanged.
2. Run `go test ./...`; the parity and contract key tests list anything
   missing.
3. Generate the catalog document for the locale:
   `go run ./cmd/catalog-doc -locale <locale> -o docs/catalog.<locale>.md`,
   and add the locale to `shipped` in `internal/catalogdoc` so the test
   keeps it current.

## Adding keys

Add each key to every shipped locale in the same change, in the pack of
the package that uses it (`<dir>/locales/<locale>/<domain>.json`) rather
than another package's pack; the default bundle takes only loop keys. Custom event types need their `summary_key`; custom session
kinds need `session.<kind>` and `scene.session.<kind>`; custom tools need
their `description_key` (or a `description`). After changing catalogs or
`contract`/`catalogdoc` keys, regenerate `docs/catalog.md` and
`docs/catalog.zh-CN.md`.
